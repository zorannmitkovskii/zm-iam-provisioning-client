# zm-iam-provisioning-client

Spring Boot starter every zm-* service pulls in to ship its
`iam-manifest.yml` to IAM at startup. Replaces the hand-rolled
`RealmInitializer` / `ClientInitializer` / `IdentityProviderInitializer`
chain in each service with one dependency + one YAML file.

---

## Install

```xml
<dependency>
  <groupId>zm</groupId>
  <artifactId>zm-iam-provisioning-client</artifactId>
  <version>0.1.0-SNAPSHOT</version>
</dependency>
```

Drop your manifest into `src/main/resources/iam-manifest.yml`. Everything
else is auto-configured.

---

## Configure

Standard Spring Boot config keys (env or `application.yml`):

| Key | Default | Purpose |
|---|---|---|
| `iam.provisioning.enabled` | `true` | Master kill switch — set to `false` in local dev without IAM. |
| `iam.provisioning.base-url` | *(required)* | Where IAM lives. `http://iam:8383` in Docker, `https://iam.internal` in prod. |
| `iam.provisioning.token` | *(required)* | Plaintext bootstrap token — the SERVICE-side pair of IAM's `IAM_PROVISIONING_TOKEN_<SERVICEID>` argon2 hash. Generated by `scripts/generate-provisioning-token.sh` in zm-iam-service. |
| `iam.provisioning.manifest-path` | `classpath:iam-manifest.yml` | Where to find the manifest. |
| `iam.provisioning.retry-max-window-seconds` | `60` | Total retry budget for transient failures (network, 5xx). Covers Docker Compose cold-start races. |
| `iam.provisioning.failure-mode` | `fail-fast` | `fail-fast` throws + kills the app; `log-and-continue` logs ERROR and lets startup finish. |

Typical prod env:

```bash
IAM_PROVISIONING_ENABLED=true
IAM_PROVISIONING_BASE_URL=http://iam:8383
IAM_PROVISIONING_TOKEN=<paste-plaintext-from-generate-token.sh>
IAM_PROVISIONING_FAILURE_MODE=fail-fast
```

## Example `iam-manifest.yml`

`${VAR}` gets substituted from the process environment before the YAML
is parsed — perfect for per-environment domains without maintaining
three manifests.

```yaml
serviceId: ivy-events-be
manifestVersion: 3

realms:
  - name: event-app
    settings:
      loginWithEmailAllowed: true
      registrationAllowed: false
    clients:
      - clientId: eventFE
        type: PUBLIC
        pkce: true
        redirectUris:
          - "https://${APP_DOMAIN}/*"
          - "http://localhost:5173/*"
      - clientId: eventBE
        type: CONFIDENTIAL
        serviceAccountsEnabled: true
    realmRoles: [USER, ADMIN, ORGANIZER, VENDOR]
    identityProviders:
      - alias: google
        type: GOOGLE
        clientIdEnvRef: IVY_GOOGLE_CLIENT_ID
        clientSecretEnvRef: IVY_GOOGLE_CLIENT_SECRET

  - name: zm-services
    clients:
      - clientId: ivy-events-be-svc      # MUST be `{serviceId}-svc`
        type: CONFIDENTIAL
        serviceAccountsEnabled: true
        serviceAccountRoles: [iam-client]
```

`APP_DOMAIN` must be set on the service's env in every environment (test:
`test.ivyevents.mk`, prod: `ivyevents.mk`). A missing env var fails
startup with a clear error naming the variable.

## Startup flow

1. On `ApplicationReadyEvent` the auto-configured listener fires.
2. `ManifestLoader` reads YAML from the classpath, resolves `${VAR}`,
   parses into DTOs, runs local Bean Validation. Failure here throws
   immediately — no HTTP call — so a typo in the YAML surfaces without
   waiting for IAM to say "400".
3. `IamProvisioningClient` POSTs the JSON body to
   `${base-url}/provisioning/manifests` with `X-Provisioning-Token`.
4. On 2xx → logs one line summarising the response (`APPLIED` +
   per-resource changes, or `NOOP` if the version was already applied).
5. On 5xx / network fail → exponential backoff (1s → 2s → 4s → …) until
   the retry window is exhausted.
6. On 4xx → immediate fail; IAM's response body (typically field-level
   validation errors) is included in the exception message so the log
   shows exactly what's wrong.
7. Final failure → `fail-fast` re-throws, killing startup so
   Docker/systemd restarts the container; `log-and-continue` logs ERROR
   and lets the app boot without provisioning.

## Turning it off in tests

The full auto-config short-circuits when `iam.provisioning.enabled=false`
— no beans registered, one DEBUG line, zero HTTP calls. Handy for
integration tests that don't want a live IAM.

```java
@TestPropertySource(properties = "iam.provisioning.enabled=false")
class MyServiceTest { ... }
```

## Sync with server

The DTOs (`ServiceProvisioningManifest` + friends) are DUPLICATED from
`zm-iam-service` on purpose — a shared "api" artifact would let the two
drift out of lockstep with the server version at random. Contract tests
here parse the same fixtures as the server and would fail if the shape
divers. Keep them aligned by hand and let the tests catch mistakes.
